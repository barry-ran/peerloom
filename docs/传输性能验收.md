## 边界

基准使用真实环回 UDP、ICE、DTLS 和可靠有序 SCTP 字节流，不替换加密、不降低可靠性、不改变流量或有界背压。它测量通用传输层的 **closed-loop 回显**，不是公网时延、单向饱和吞吐、授权控制面或 FFI/Android/Apple 整机性能。固定四个 Tokio worker；每个连接独立建立两个 PeerTransport。先预热和同步，再测量；FIN、反向 FIN 及关闭校验成功且进程退出码为 0 才接纳结果。

## 重现

从仓库根目录执行；构建使用 `src/device-sdk` 锁定工具链：

```sh
(cd src/device-sdk && cargo build --locked --release -p device-transport-webrtc --example stream_perf)
# 将每个已验证版本的可执行文件保存为不同路径，不能覆盖旧版本。
python3 scripts/test-stream-performance.py \
  --binary baseline=/absolute/path/baseline \
  --binary candidate=/absolute/path/candidate \
  --output /absolute/path/results.jsonl
```

脚本参数中的路径是从仓库根执行的示例；实际构建产物在 Cargo target 目录。默认覆盖 64 B / 16 KiB、1/32/100/300/500 连接，每条件五次 AB/BA 交错。原始记录包含可执行文件 SHA-256、系统、线程数、参数、退出状态和 stderr。`wall_s < 1` 的记录标为无效，应增加轮次，不用短样本宣称收益。

CPU user/sys 在计时区读取 Linux `/proc/self/stat`；时钟粒度由 `CLK_TCK` 提供，默认 100 Hz。报告 `CPU ns/byte` 及 user/sys，不能将多线程 CPU 秒与墙钟秒混淆。字节数是双向应用有效载荷；RTT 从发起写入到完整回显核对完成，包含背压等待。预分配样本存储，排序/合并在计时后。每条件 180 秒总上限，超时失败，不跳过失败连接或把部分传输当成功。

性能比较必须在同机同构建参数同流量、无并行编译干扰下执行，并披露波动范围。分配/CPU profile 必须另跑，不能把插桩运行时间混入性能结果。`PEERLOOM_PERF_THREADS=0` 仅供单线程 profile；不可与四线程性能数据混合比较。

## 试验设计与统计

- 基线产品：`c2810089`（精确恢复 master 的 903 个 blob）；独立工作分支：`codex/peerloom-performance-20261030`。历史本地基准提交 `d609d13` 不修改运行时实现；该标识不代表已恢复的提交对象。
- 云端 Linux x86_64、9 个可见逻辑 CPU、4 个 Tokio worker、release 构建。使用仓库锁定 Rust 1.99.1 与依赖，不关闭 DTLS、不替换可靠有序 SCTP、不改变授权或背压限制。
- 通用字节流：64B / 16KiB，1/32/100/300/500 个环回连接；每条件 5 对 AB/BA 交错，实际为 3AB/2BA，不声称消除了全部时间偏差。每个进程先建连和预热，再测量；逐字节、FIN、关闭与退出成功后接纳。
- SDK worker：真实传输配合测试授权夹具，满四槽队列静置 5 秒，然后每连接 200 轮恢复；每条件 3 对。恢复时延不是公网 RTT；paced 吞吐包含人为错开的读间隔，不是饱和吞吐。正式样本关闭 poll 计数与 LD_PRELOAD。
- 变化率为每个条件的 `100 × (exp(mean(log(候选 / 基线))) − 1)`；相同 repeat 配对，不汇总不同负载作无权重“总体收益”。CPU 与延迟负数更好，吞吐正数更好。
- 对运行级配对 log-ratio 作固定 seed=0 的 10,000 次 bootstrap，取描述性 95% 区间。只有 3 或 5 对，区间覆盖能力有限；没有多指标/多条件校正，不能作为生产环境无回归的保证。RTT 是每次运行分位数之间的配对，不能把数万消息当数万独立重复。
- CPU 为计时窗口整个进程 `user+sys` 秒除以有效载荷；不是 CPU 占用率或每线程时间。`/proc/self/stat` 为 100Hz 粒度，尤其单连接 worker CPU 量化显著。分配累计量不等于峰值 RSS。
