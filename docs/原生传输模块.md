# 原生传输模块

`device-transport-webrtc` 使用固定 `webrtc/rtc 0.21.1`、Tokio 和 ring，提供真实 PeerConnection 与 DataChannel 适配。它不是平台 SDK：调用前必须由已实现的控制面信令校验对端身份和会话权限，不能把传输握手当作业务授权。

```mermaid
flowchart LR
    A[受信任的 SDP 交换] --> T[PeerTransport]
    T --> ICE[ICE]
    ICE --> DTLS[强制 DTLS]
    DTLS --> SCTP[SCTP 与 DataChannel]
    SCTP --> M[可靠消息或低延迟消息]
```

当前优先等待完整 ICE 收集后交换 SDP；`auto` 在原收集截止到达时，可使用同一 PeerConnection 已验证、含非中继候选的有限快照继续协商。仅允许一次初始协商。trickle ICE、ICE restart、自动重连、动态切路尚未集成。可靠字节流使用独立 ByteStream 与既有 stream.v1 帧协议；消息 API 的 ReliableStream 参数仍返回 Unsupported，不把消息接口冒充字节流。

`auto` 使用普通 ICE，`relay_only` 要求 TURN 配置并设置 Relay 策略；`direct_only` 拒绝本地 TURN 配置及含中继候选的远端 SDP，行为保守且失败关闭。直连与强制中继均已真实验收；TURN 测试直接查询 ICE transport 的 selected candidate pair，双方均为 Relay，并验证错误密码失败。不可达 TURN 与可达 host 共存时，Auto 的有界快照回退由真实 UDP 黑洞测试覆盖；这不代表复杂 NAT、弱网或动态切路已验收。

Auto 收集使用单一绝对截止（默认20秒），不是整个业务建连的总截止。候选回调只发有界通知；等待方从当前 peer 读取上游生成的原生 SDP（保留 DTLS 指纹），经过既有候选格式、策略及默认64KiB上限检查后最多保留一份快照；DTLS 安全仍由原生 WebRTC 执行。截止后不额外等待锁或读取 SDP；没有可用非中继候选则仍返回 Timeout。RelayOnly 不使用该回退，不能以直连冒充强制中继。关闭会立即取消收集等待；SDK worker 及 actor 在发送描述与交付 Ready 前复核同代授权、租约和安装 reset gate。

`gathering_outcome()` 区分 `Pending`、`Complete`、`PartialAtDeadline`。部分快照不伪称收集完成，晚到候选不会自动补发；没有新增 trickle 协议或手工拼接候选。显式 CI 黑洞测试覆盖真实 TURN datagram、双端 Host/Host 选中路径、DTLS 与二进制互通、RelayOnly 拒绝以及收集中关闭；默认20秒配置另有45秒双端总上限。Linux真实 Go/PG/Redis/C 压力测试还验证坏共享中继配置下原45秒建连及身份重置，不把其未读取的 selected-pair 类型冒称为已观测。

```sh
cargo test -p device-transport-webrtc --test auto_unreachable_turn --locked -- --ignored --nocapture
```

默认关闭 mDNS（可显式启用）：当前原生部署不依赖 multicast，避免没有组播接口的环境在 PeerConnection 创建时失败。浏览器互通后置；关闭 mDNS 不关闭 DTLS。错误按 I/O、SDP、ICE、TURN、DTLS、SCTP 等脱敏分类，不直接输出可能含凭证的底层错误。

资源限制分层设置：消息和 SDP 默认最大 64 KiB，发送缓存/SCTP 接收缓存默认 1 MiB，通道数默认 8，操作默认 20 秒且配置有上限。上游每通道事件队列固定 256 项并背压，适配器等待打开时最多保留一条有限消息。payload 限额不等于整个进程内存限额，事件队列、SCTP 与分配器各有开销。

通道数是本 PeerTransport 生命周期累计限制，关闭单个通道不回收名额；重建 PeerTransport 才重置。调用者必须显式 `close().await`，关闭有超时；不在 Drop 内偷偷创建后台任务。消息发送不代表业务消费，也不保证断线恢复 exactly-once。

当前 workspace 默认测试 54 项通过；传输还经过 fmt、严格 clippy 与 release 构建。真实本地 UDP 测试单独执行：

```sh
cd src/device-sdk
cargo test -p device-transport-webrtc --test native_pair --locked -- --ignored --nocapture
```

三个原生集成测试覆盖 ICE 候选与 DTLS 指纹、可靠/低延迟双向收发、中文/二进制、大小限制、关闭、重复协商拒绝，并发发送的原子缓存配额，以及 100 次连续建连关闭。本次约 60 秒，不代表吞吐或 P95 SLA。CI 显式运行 ignored 网络测试，普通 cargo test 的通过不能替代它。

`turn_pair` 在受控 coturn 4.18.0 上验证 relay-only 双端可靠/低延迟消息、严格 Relay/Relay 选中路径、错误凭证拒绝及恢复。`authorized_pair` 经过真实 Go/PG/Redis 完成目标确认、SDP 路由与数据交换，并验证 WSS 断开不立即切断数据、授权单调期限到达关闭通道。

本模块不能替代高层 SDK 的授权、租约及五端业务闭环验收；远端 CI 验收以精确提交为准。

## 可靠字节流（传输层子集）

新增类型化 `create_stream` / `accept_stream` 返回 `ByteStream`，协议名 `peerloom.stream.v1`，仅接收可靠有序、无重传次数/寿命限制的 DataChannel。普通 `create_channel(ReliableStream)` 仍拒绝，以免调用者把返回的消息接口误当字节流。

帧含版本标识、类型、64位递增序号和长度；wait_open 双向交换 seq0 的 SETTINGS 接收上限，发送分片取双方较小值且最多16KiB，DATA 从 seq1 开始。`write` 返回本次实际接纳的字节数；缓存满时原子返回 BufferFull、不推进序号、不丢弃旧字节。`read` 按调用方缓冲偏移消费，不保留发送消息边界，内部仅保留一个有界分片。显式 FIN 结束单方向，另一方向仍可响应；底层异常关闭不能冒充有序 EOF。`close` 是双向中止，不宣称未消费数据已送达。

取消发送 future 后若结果不确定，后续 API 拒绝继续，不猜测重放；资源回收仍需显式 close/PeerTransport.close，不在 Drop 自动创建清理任务。发送计数耗尽、格式或顺序错误同样不能静默继续。它不是 Tokio AsyncRead/AsyncWrite trait，也尚未接入高层 DeviceSdk、授权租约包装或 C ABI；不能绕过业务授权直接当完整 SDK 使用。

本地真实 UDP 测试覆盖256KiB分片与偏移读、双向 FIN、128字节发送配额背压恢复、错误协议拒绝与异常 EOF。不同端接收上限通过 SETTINGS 协商，已验证默认64KiB消息上限与128字节上限互通；最小消息容量须容纳21字节设置帧。取消等待对端设置可重试且不重发本端设置。SDK 级 TTL/重连及跨平台封装仍待集成。

## 混合通道分派与累计预算

混合可靠消息、可靠字节流、低延迟消息时，只运行一个 `accept_incoming()` 循环，按 `IncomingChannel` 三个变体交给各自有界消费者。不要并行运行 `accept_channel` 和 `accept_stream` 抢同一到达队列。兼容的 `accept_channel` 仍是原始消息接口，不检查应用协议；`accept_stream` 经同一类型校验，收到消息或未知类型时关闭并返回 Protocol。

类型由 DCEP 元数据决定，不信任 label：空 protocol、有序且无重传/寿命限制是 reliable_message；空 protocol、无序且 max_retransmits=0、无寿命限制是 low_latency_message；`peerloom.stream.v1` 必须有序且无重传/寿命限制。其他组合失败关闭，不静默降级。没有新增线协议或自定义加密。先建至少一个初始通道生成 SCTP m-line，协商完成后可从双方热开其余通道，不重复交换 SDP。

`max_channels` 仍是双向合计的生命周期创建预算，工程默认8、配置范围1–1024，同时约束存活通道总数；不是可回收的 active-only 配额。上游 rtc0.21.1 的 SCTPStreamClosed 才移除 registry 项，close API 返回不能证明该事件和全部后台队列都已回收，因此正常关闭不返还预算。create 超时结果不确定，同样保留已预占名额；不通过不断 close/create 绕过累计上限。需要新预算须先关闭整个已授权连接并按高层策略重建，不能自动续租。

`mixed_channels` 为显式 ignored 的真实 UDP 验收：双方完成一次 SDP 后热开三种同 label 通道，核验准确类型、双向二进制消息、流偏移读与 FIN、慢应用流读取时其他通道可用、子通道关闭不影响兄弟，以及关闭后仍耗尽累计配额。普通离线单测只验证元数据允许表与拒绝表，不能替代真实网络门禁：

```sh
cargo test -p device-transport-webrtc --test mixed_channels --locked -- --ignored --nocapture
```

此入口仅是传输层积木，尚未把多通道接入 DeviceSdk/C ABI/Kotlin/Swift；其句柄必须由后续高层绑定同一会话代号、安装 reset gate 与租约。
