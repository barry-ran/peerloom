# 原生传输模块

`device-transport-webrtc` 使用固定 `webrtc/rtc 0.21.1`、Tokio 和 ring，提供真实 PeerConnection 与 DataChannel 适配。它不是平台 SDK：调用前必须由已实现的控制面信令校验对端身份和会话权限，不能把传输握手当作业务授权。

```mermaid
flowchart LR
    A[受信任的 SDP 交换] --> T[PeerTransport]
    T --> ICE[ICE]
    ICE --> DTLS[强制 DTLS]
    DTLS --> SCTP[SCTP 与 DataChannel]
    SCTP --> M[可靠消息或低延迟消息]
```

当前采用完整 ICE 收集后交换 SDP；仅允许一次初始协商。trickle ICE、ICE restart、自动重连、动态切路尚未集成。可靠字节流明确返回 Unsupported，不用消息通道冒充流协议。

`auto` 使用普通 ICE，`relay_only` 要求 TURN 配置并设置 Relay 策略；`direct_only` 拒绝本地 TURN 配置及含中继候选的远端 SDP，行为保守且失败关闭。直连与强制中继均已真实验收；TURN 测试直接查询 ICE transport 的 selected candidate pair，双方均为 Relay，并验证错误密码失败。auto 失败兜底与复杂 NAT/弱网仍待验收。

默认关闭 mDNS（可显式启用）：当前原生部署不依赖 multicast，避免没有组播接口的环境在 PeerConnection 创建时失败。浏览器互通后置；关闭 mDNS 不关闭 DTLS。错误按 I/O、SDP、ICE、TURN、DTLS、SCTP 等脱敏分类，不直接输出可能含凭证的底层错误。

资源限制分层设置：消息和 SDP 默认最大 64 KiB，发送缓存/SCTP 接收缓存默认 1 MiB，通道数默认 8，操作默认 20 秒且配置有上限。上游每通道事件队列固定 256 项并背压，适配器等待打开时最多保留一条有限消息。payload 限额不等于整个进程内存限额，事件队列、SCTP 与分配器各有开销。

通道数是本 PeerTransport 生命周期累计限制，关闭单个通道不回收名额；重建 PeerTransport 才重置。调用者必须显式 `close().await`，关闭有超时；不在 Drop 内偷偷创建后台任务。消息发送不代表业务消费，也不保证断线恢复 exactly-once。

当前 workspace 默认测试 54 项通过；传输还经过 fmt、严格 clippy 与 release 构建。真实本地 UDP 测试单独执行：

```sh
cd src/device-sdk
cargo test -p device-transport-webrtc --test native_pair --locked -- --ignored --nocapture
```

三个原生集成测试覆盖 ICE 候选与 DTLS 指纹、可靠/低延迟双向收发、中文/二进制、大小限制、关闭、重复协商拒绝，并发发送的原子缓存配额，以及 100 次连续建连关闭。本次约 60 秒，不代表吞吐或 P95 SLA。CI 显式运行 ignored 网络测试，普通 cargo test 的通过不能替代它。

`turn_pair` 在受控 coturn 4.18.0 上验证 relay-only 双端可靠/低延迟消息、严格 Relay/Relay 选中路径、错误凭证拒绝及恢复。`authorized_pair` 经过真实 Go/PG/Redis 完成目标确认、SDP 路由与数据交换，并验证 WSS 断开不立即切断数据、授权单调期限到达关闭通道。

尚未交付弱网/其他原生平台、自动重连、可靠流、C ABI 与五端示例；新组合的远端 CI 验收以精确提交为准。

## 可靠字节流（传输层子集）

新增类型化 `create_stream` / `accept_stream` 返回 `ByteStream`，协议名 `peerloom.stream.v1`，仅接收可靠有序、无重传次数/寿命限制的 DataChannel。普通 `create_channel(ReliableStream)` 仍拒绝，以免调用者把返回的消息接口误当字节流。

帧含版本标识、类型、64位递增序号和长度；wait_open 双向交换 seq0 的 SETTINGS 接收上限，发送分片取双方较小值且最多16KiB，DATA 从 seq1 开始。`write` 返回本次实际接纳的字节数；缓存满时原子返回 BufferFull、不推进序号、不丢弃旧字节。`read` 按调用方缓冲偏移消费，不保留发送消息边界，内部仅保留一个有界分片。显式 FIN 结束单方向，另一方向仍可响应；底层异常关闭不能冒充有序 EOF。`close` 是双向中止，不宣称未消费数据已送达。

取消发送 future 后若结果不确定，后续 API 拒绝继续，不猜测重放；资源回收仍需显式 close/PeerTransport.close，不在 Drop 自动创建清理任务。发送计数耗尽、格式或顺序错误同样不能静默继续。它不是 Tokio AsyncRead/AsyncWrite trait，也尚未接入高层 DeviceSdk、授权租约包装或 C ABI；不能绕过业务授权直接当完整 SDK 使用。

本地真实 UDP 测试覆盖256KiB分片与偏移读、双向 FIN、128字节发送配额背压恢复、错误协议拒绝与异常 EOF。不同端接收上限通过 SETTINGS 协商，已验证默认64KiB消息上限与128字节上限互通；最小消息容量须容纳21字节设置帧。取消等待对端设置可重试且不重发本端设置。SDK 级 TTL/重连及跨平台封装仍待集成。
